# 自助导学 · 试卷系统功能设计（AI 出卷 + 在线作答 + AI 批改 + 手写）

> 版本：v1.0（设计稿）｜日期：2026-10-21
> 定位：在现有 homework-farm 小程序 + 全科导学（画像/计划/错题/复测/复习）基础上，新增「试卷」能力，并扩展一个**原生 iPad App** 作为双端之一。
> 已确认选型：① iPad = 原生 Swift App；② 批改 = OCR+文本 AI（默认）与 视觉模型（可配置）双路线；③ MVP = AI 出卷 + 在线作答 + AI 批改（手写/上传为第二阶段）。

---

## 一、目标与范围

### MVP（第一版，先跑通闭环）
1. **学情驱动 AI 出卷**：根据儿童画像（年级/讲解偏好）、成长计划进度、近期错题（E1-E9），AI 自动生成一份结构化试卷（含参考答案/解析）。
2. **双端可创建试卷**：小程序端、iPad 端均可触发 AI 出卷与手动组卷。
3. **在线作答 + 提交**：屏幕内作答（选择题/填空题/计算题/简答/画板），提交后调用 AI 批改。
4. **AI 批改（双路线）**：默认 OCR+文本 AI 判分；可配置升级到视觉模型直接看图批改。
5. **错题回流闭环**：批改判错的题自动归因（E1-E9）写入错题本 → 触发复测/复习卡，复用现有导学闭环，不另起学情系统。

### Phase 2（第二阶段，设计预留）
6. **Word/PDF 上传 → 转可书写**：上传 .docx/.pdf → 云端转渲染图 → 前端叠加书写层（Canvas/PencilKit）→ 提交批改。

│  在线作答/批改报告    │        │                      │
└──────────┬──────────┘        └──────────┬──────────┘
           │                              │
           │   CloudBase 云函数 (HTTPS/SDK) │
           ▼                              ▼
┌──────────────────────────────────────────────────────────┐
│                     CloudBase 后端（共享）                  │
│  tutorSync(同步/试卷只读→扩展)  tutorChat(导学/诊断)        │

**铁律**：双端共用同一 CloudBase 后端与同一份「学情」数据（画像/计划/错题），绝不各建一套。试卷与批改结果经统一身份按 `openid` 隔离。

## 三、身份与数据隔离方案（关键决策）

**问题**：小程序用 `event.userInfo.openId`（微信身份）；iPad 原生 App 不是微信环境，拿不到 wx openid，但必须与小程序共享同一份试卷/错题数据。

**方案（推荐，复用现有「网页绑定」思路）**：
1. **iPad 端身份**：通过 CloudBase **自定义登录（custom login）** 获得稳定 `uid`（匿名/自定义均可）。
2. **账号绑定**：复用 `webPortalBind` 模式 —— 小程序端生成一次性绑定令牌，`iPad 端输入令牌`完成「本机 iPad ↔ 微信 openid」绑定；绑定后写入映射表 `exam_account_link{uuid↔openid}`。
3. **云函数统一身份解析**：新增 `resolveOpenid(event)` 助手（置于 `scripts/` 或云函数公共模块）：
   - 小程序调用：`event.userInfo.openId` 存在 → 直接用。
   - iPad 调用：从自定义登录 token 解析 `uid` → 查 `exam_account_link` 得 `openid`。
   - 现有 `tutorChat/tutorSync/tutorRetest` 不改即跑（它们只读 wx openid）；新 `examGen/examGrade` 用统一解析，保证 iPad 端也能读写同一份数据。

> 注：现有云函数已深度依赖 `event.userInfo.openId`，全量改造风险高。**仅新云函数 + 被 iPad 直连读取的函数（tutorSync 的 exams/pull）需接入 `resolveOpenid`**，其余保持不动。

## 四、数据模型设计

### 4.1 `exam_resources`（扩展，现集合）
保留现有字段（name/subject/subjectName/level/examType/knowledgePoints/suggestedDuration/markdown/answers/sourceFile/sessionFile 等），新增：

| 新字段 | 类型 | 说明 |
|--------|------|------|
| `origin` | string | `ai`(AI出卷) / `manual`(手动) / `workbench`(原工作台推送) / `upload`(Phase2上传)。旧数据默认 `workbench` |
| `questions` | array | 结构化题目，供在线作答与 AI 批改（详见 4.3） |
| `grade` | string | 适用年级（已存在，补全） |
| `status` | string | `draft`(草稿) / `published`(已发布可作答) |
| `createdBy` | string | `mini` / `ipad` / `workbench` |

### 4.2 `tutor_exam_submissions`（新集合）
每次提交批改落一条：

```js
{
  openid, clientId,                 // clientId = 本地 uid，跨设备去重
  examClientId, examName, subject, subjectName,
  route: 'ocr_text' | 'vision',     // 走的批改路线
  answers: [                        // 逐题作答
    { qid, type, text?, imageRefs?:[fileId], ocrText?,
      correct?: bool, score?, diagnosis?: { errorType, errorDesc, suggestion } }
  ],
  summary: { total, correctCount, rate, strengths:[], weaknesses:[], advice },
  createdAt, status: 'graded' | 'pending'
}
```

### 4.3 结构化题目 `questions[]`
```js
{ id, type:'choice'|'fill'|'calc'|'essay'|'draw',
  stem, options?:[string], answer, points?:number,
  kp?:string,            // 关联知识点（用于出题时从薄弱点组卷）
  difficulty?:1|2|3,
  imageRefs?:[fileId] }  // draw 题型底图（Phase2 上传书写）
```

### 4.4 同步契约（沿用 R1–R7）
- `exam_resources` 经 `tutorSync` 的 `exams/exam` 读写；列表仍只回索引、详情回正文（保持轻量）。
- `tutor_exam_submissions` 加入 `tutorSync` 的 pull/push（KINDS 增加 `examSubs`），按 `clientId` 去重，墓碑机制同错题本。
- `tutorStore.js` 增加 `examSubs` 本地读写出口（仿 `mistakes` 实现，遵循 commit() 落盘+登记上云队列）。

## 五、AI 出卷（examGen 云函数）

**入参**：
```
action: 'gen'
subject, grade, teachStyle, expectations,   // 来自 learnerProfile
planCtx: { currentStage, pendingTasks[], coveredKp[] },  // 来自 studyPlan 进度
learnerCtx: string,                          // 近期错题快照（tutorStore.getLearnerContext 组装）
scope: { mode:'auto'|'unit'|'type'|'chapter', count, difficulty, examType }
```

**Prompt 设计**（复用 `tutorChat` 的 hy3 + retry + `no_pack` 兜底 + `sanitizeBanned` 合规门禁）：
- **System**：定位为「自适应组卷老师」，原则「哪里弱考哪里、不超纲、不编造题/答案」。
- **上下文注入**（与 tutorChat.buildMessages 同构）：画像 + 计划进度（优先未掌握/滞后点）+ 近期错题（E 码错因）→ 让 AI 围绕薄弱点出题。
- **输出**：严格 JSON `{ name, examType, suggestedDuration, knowledgePoints[], questions:[…结构化], answersMarkdown }`，`extractJson` 防御解析。
- **落库**：写 `exam_resources`（origin='ai'）+ 回传客户端；客户端再 `tutorSync.push` 补写（离线可用）。

**出题策略（"自适应"的核心）**：
- `mode:'auto'` → 从 `pendingTasks 薄弱点 ∪ 近期错题 topic` 抽取 60% 题，剩余 40% 从已覆盖知识点随机巩固。
- `mode:'unit'/'chapter'` → 限定范围；`mode:'type'` → 限定题型（专项练）。

## 六、在线作答与手写

### 小程序端
- 新增 `pages/examAnswer`（在线作答）：按 `questions[]` 渲染题型组件（choice 点选 / fill 输入 / calc 输入 / essay 输入 / draw 用 `<canvas>` 触摸书写）。
- `draw` 题型：canvas 手绘，导出图片 `wx.canvasToTempFilePath` → 上传云存储得 `fileId`。

### iPad 原生 App（SwiftUI）
- 书写用 **PencilKit**（`PKCanvasView`）：Apple Pencil 压感、 palm rejection、笔迹自然。
- 题型组件用 SwiftUI 原生实现；`draw` 题直接用 PencilKit 画板。
- 提交：把作答（文本 + 手写图片 `Data`）经 HTTPS 调 `examGrade`。

## 七、AI 批改（examGrade 云函数，双路线可配置）

**入参**：`examClientId`（取参考答案/结构化答案） + `answers[]`（文本或图片 fileId） + `route`(可选，缺省按配置) + 画像。

### 路线 A：OCR + 文本 AI（默认，零额外成本）
1. 手写/画板图片先经 **OCR**（CloudBase 文档识别 / 或轻量 OCR 服务）转 `ocrText`。
2. 把 `ocrText` + 题目 `stem/answer` + 参考答案 送 **hy3**（复用 `tutorChat` 的 DIAGQ_PROMPT 同构 + `sanitizeBanned`）。
3. 输出逐题 `correct/score/diagnosis(E1-E9)` + 总评 `summary`。

### 路线 B：视觉模型（可配置，更准）
- 当 `route:'vision'` 或服务配置开启且遇图形/复杂手写题时，把底图+作答图送**外部视觉模型**（Qwen-VL / GLM-VL）。
- **密钥与成本**：provider/key 走环境变量/安全配置（不落库、不进前端），**默认关闭**，用户自备；失败时**自动降级到路线 A**（不阻塞批改）。

### 批改输出与回流（核心集成点）
- 每道判错题 → 调诊断 → 写 `tutor_mistakes`（新增 `source:'exam'`，与 `photo/tutor/manual` 并列）→ 出现在错题本 → 触发复测/复习卡。
- 总评 `summary` 回写试卷/提交记录，并在导学报告（report）增加「试卷表现」维度。
- **绝不自动判定掌握**（守「活动≠证据≠掌握」契约）：批改只给「达标/未达标」与错因，掌握由人确认。

## 八、与现有导学闭环的回流（系统价值核心）

```
AI出卷(薄弱点组卷) ──▶ 在线作答 ──▶ AI批改(逐题诊断E1-E9)
                                    │
                          ┌─────────┴─────────┐
                          ▼                   ▼
                    写入错题本(ource:exam)   总评→导学报告
                          │
                          ▼
                    复测(tutorRetest) + 复习卡/窗口
                          │
                          ▼
                    掌握确认(人) → 出卷时该点降权
```

- 出卷、批改、错题、复测全部复用现有 `tutorStore` / `tutorChat` / `tutorRetest` 机制，**不新建学情引擎**。
- 错题本新增 `exam` 来源只是加一个枚举值，现有筛选/订正/复测流程零改动即可收纳试卷错题。

## 九、Phase 2：Word/PDF 上传转可书写（设计预留）

1. **上传**：iPad/小程序上传 `.docx/.pdf` → 云存储得 `fileId`。
2. **转渲染图**：云函数/云托管服务用 LibreOffice/Pandoc 或文档服务将文件转 PDF → 逐页渲染为图片（`pdf2image`/腾讯云文档服务）。
3. **可书写层**：前端把页图作底图，叠加透明书写层（小程序 canvas / iPad PencilKit）；书写与底图分离存储。
4. **提交批改**：书写层图片 + 底图 → OCR（路线A）或视觉模型（路线B）判分。
5. **存储**：页图与书写层存 CloudBase 云存储；`exam_resources` 新增 `origin:'upload'` + `pages:[{imageFileId, writeFileId}]`。

## 十一、合规与风险

1. **个人主体小程序审核红线**：继续规避「作业/学习/教育/培训」；现有 `examGallery` 已用「试卷库」一词，需评估风险（iPad 原生端不受微信审核约束，可更自由）。UI 层对小程序端可改用「测验卷/导学卷」等中性词。
2. **AI 幻觉**：出卷/判分加「不编造题/答案/评分标准」硬约束 + 结构化输出 + 解析兜底；关键题建议人工复核。
3. **视觉模型成本**：默认关闭、按量计费、用户自备密钥；OCR 失败/视觉失败均降级到文本 AI，不阻塞主流程。
4. **CloudBase 低配套餐无视觉模型**：MVP 默认路线 A（OCR+文本）即为此设计，无需视觉模型即可跑通。
5. **跨端身份一致性**：绑定令牌一次性 + 可解绑，避免账号错绑导致数据串号。

## 十三、待确认事项（设计评审前 → 已于 2026-10-21 确认）

| # | 问题 | 决策（已确认） |
|---|------|----------------|
| 1 | 双端账号关系 | **不强制绑定**：有账号则账号优先（绑定到微信 openid 共享数据）；无账号则 iPad 独立账号（数据独立、不互通）。绑定为可选增强，非阻塞项。 |
| 2 | 视觉模型 provider | 用户自备密钥，**主流模型全部默认内置下拉可选**（Qwen-VL / GLM-VL / Doubao-VL / Gemini / GPT-4o 等）；配置 API key 后支持「测试连接」验证是否成功。默认关闭，失败降级 OCR+文本。 |
| 3 | 小程序端文案 | 用中性词 **「测验卷」**（不用「试卷」），规避个人主体审核红线；iPad 原生端不受微信约束可用「试卷」。 |
| 4 | OCR 服务 | 默认先用 **CloudBase 内置文档识别**，成本可控；后续可切独立 OCR。 |

> 决策落地影响：
> - 身份方案改为「可选绑定」：iPad 端默认以自定义登录 `uid` 独立运行；绑定令牌仅在有共享需求时输入。`resolveOpenid` 优先用绑定映射，否则回退到调用方自身身份（wx openid 或 iPad uid）。
> - 新增「视觉模型配置」模块：provider 注册表 + 密钥安全存储（环境变量/安全配置，不落库不进前端）+ 测试连接接口。
> - 小程序端 UI 文案统一「测验卷 / AI 出卷 / 我的测验卷」。
