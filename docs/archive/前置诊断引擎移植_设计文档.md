# 前置诊断引擎移植 · 设计文档

> 日期：2026-11-11 · 思路来源：`_ref_cn-math-taxonomy/diagnose/engine.js`（只读参考，CC BY-NC 4.0）
> 本轮范围：**设计 + 独立纯函数模块 + 单测**。不改 tutorStore / tutorChat / examService，不写云端，不新增数据字段。

## 0. 一句话结论

把参考库四步机制移植成**会话内的「前置欠账假设」生成器**，输出给现有 E1-E9 与出题入口当上下文；难度四档作为**出题序列调度策略**，不改任何 JSON schema。三态一律标 `provisional`，永不写 `done`/证据。

## 1. 现状盘点（已读代码，非凭记忆）

| 能力 | 位置 | 现状 |
|---|---|---|
| E1-E9 错因 | `miniprogram/utils/mistakeRules.js` `ERROR_TYPES`；`cloudfunctions/tutorChat/index.js` `DIAG_PROMPT` / `DIAGQ_PROMPT` | 单次作答/对话的**诊断假设**，静态归因，无前置链 |
| 前置边 | `tutorStore.js` `normPointMeta` → `prereqs:[{topic,strength,reason}]`；`getUnitKpsMastery` | 已有静态比对，产出 `missingPrereqs[]` + `blocks[]`，**无根因、无三态** |
| 掌握判据 | `tutorStore.js` 卡片 `done=true`（Leitner 毕业）；`tutorRetest` ≥5 题、≥80%、`independence` | **证据契约**：活动≠证据≠掌握 |
| 出题盲区提示 | `examService.buildBlindSpotHint`（已含「适当降低难度」）、`studyPlanGen.buildPrereqBlock` | 已有注入点，缺「根因」与「难度序列」 |
| 难度 | `examService` 题目 `difficulty: 1..3`（数字） | 只有静态档位，无随作答推进的梯度 |
| 闪卡 | `tutorStore.getCards` 按 `dueAt` 排序、`advanceCard` box 1–5 | 无难度概念 |

## 2. 第一性原理：两条冲突，必须先裁决

1. **维度不同，不能合并字段。** E1-E9 描述「这次作答的认知失误类型」，`weak/shaky/root` 描述「知识点掌握状态」。把 weak 硬塞成某个 E 编号是范畴错误。正确做法：新增**独立的一层归因先验**，只作为 prompt 上下文，不新增标签、不改 `errorType`。
2. **证据等级不同，不能叫掌握。** 参考库 `mastered` 是会话内推定（默认连对 3 题）；本地掌握必须走 `tutorRetest` 五题 80% + 独立性。移植后状态命名 `provisionalMastered`，输出恒带 `isEvidence:false`，`confirm` 默认 **5**（对齐五题口径）。

## 3. 语义对齐：三态 → E1-E9 先验

| 引擎状态 | 含义 | 给 DIAG_PROMPT 的先验（不改 errorType） |
|---|---|---|
| `shaky`（首错，基础确认题答对） | 会，但不稳 | 优先复核 **E1 审题 / E7 信息处理 / E9 检查迁移**；别急着判概念不会 |
| `weak`（基础确认题也错） | 该点本身没打牢 | 优先复核 **E2 概念 / E3 表征**；不是本次粗心 |
| `root`（无 weak 先修的 weak 节点） | 根因在前置 | 提示**别把 E2 归到当前点**，应归到 root 对应的前置知识点 |
| `provisionalMastered` | 会话内推定 | 仅作调度信号，**不写 done、不产证据、不在 UI 声称掌握** |

## 4. 难度四档的落点（零 schema 变更）

- 档位 `basic → standard → challenge → advanced`，只作**出题序列调度**，不写进 card / question 对象。
- 与 `examService` 的 `difficulty:1..3` 映射（保守、防超纲）：`basic→1, standard→1, challenge→2, advanced→3`。
- 调度规则：探针首题 basic/standard；连对逐档上推；**答错后的确认题强制回退 basic**；闪卡复习按 `box` 决定起点（box 1→basic，3→standard，5→challenge）。
- 同日到期卡排序：`dueAt` 优先，其次 `box` 升序（弱卡先出 basic），返回新数组，不改原对象。

## 5. 模块契约（`miniprogram/utils/prereqDiagnosis.js`）

CommonJS、无 `wx` 依赖、纯函数、可被 Node 直接 require。所有输入不修改，`applyAnswer` 返回新 session。

| 导出 | 签名 | 说明 |
|---|---|---|
| `createSession` | `({points, targets, limit=16, confirm=5, seed}) → session` | 以 `kpId` 优先、`topic` 兜底建图；取 targets 的 hard+soft 祖先做拓扑序，但 **stack 初始只含 targets（逆序）**，祖先在答错后才回溯 |
| `nextItem` | `(session) → {topicId, topic, phase, difficulty, examDifficulty, qid, prompt, answer} \| null` | `phase: 'probe' \| 'confirm'`；**不生成题目**，只给调度信号，题干取 `assessmentPrompt \|\| front`、答案取 `back`，接入时由调用方挂题库 |
| `applyAnswer` | `(session, result) → newSession` | `result: 'correct' \| 'wrong' \| 'skip'`；实现四步状态机 |
| `summarize` | `(session) → {status, roots, shaky, weak, provisionalMastered, path, blindSpotHint, e1e9Hint, isEvidence:false}` | `roots` = weak 且无 weak hard 先修；`path` = roots ∪ shaky 及后代，去掉推定掌握 |
| `DIFFICULTY_ORDER` / `pickDifficulty` / `toExamDifficulty` / `sortCardsForReview` | 纯函数 | 难度四档调度与闪卡排序 |

**状态机（移植并改造参考库四步）**
1. 探针题：按 `pickDifficulty` 出；连对满 `confirm` 且无失败 → `provisionalMastered`，祖先标 `inferred`（不覆盖 direct）。
2. 首次 wrong/skip：不结论，出**基础确认题**（难度强制 basic）。
3. 确认题 correct → `shaky`，不回溯；确认题 wrong/skip 或无题可出 → `weak`，把该点 `prereqs` 按 **hard 先、soft 后**压栈。
4. 题量用尽仍有未确认错误 → 按 `weak/unconfirmed` 处理，`roots` 照常算。
